# 1枠の外見差し替え試作 0.2.2

## 0.2.2 の変更（以下の旧方式の説明に優先）

0.2.1の実機ログでは適用5回すべてで比較対象の配置・効果が一致し、例外も出ていませんでしたが、
画面では置換後の外見が見えませんでした。描画情報が足りないため原因は未確定です。

0.2.2では既存Rendererのメッシュ・材質を書き換えず、厳格な単純構造チェックを通過した外見Prefabを
複製し、元オブジェクトと同じ親・配置位置に表示します。外見側Prefabの回転・スケール・Renderer設定を保持し、
レイヤーは元に合わせます。元はRendererのみ非表示にし、OFFではその状態を復元、外見複製を破棄します。
棚・スクリプト・Collider付きなどは従来通り拒否します。配置IDと効果の扱いは変更しません。

`RenderBefore` / `RenderAfter` に位置・スケール・メッシュ頂点数・Bounds・シェーダー・描画状態・
静的バッチ状態を記録します。これらは描画不具合の切り分け用で、表示成功の保証ではありません。
開店中にパネルON/OFFで確認してください。前回OFFで終了した場合はONへ切り替えが必要です。
ビルド成功（警告0・エラー0）、実機未検証。

## 0.2.1以前の経緯

0.2.1: 編集中・無効化中にもパネルの情報を更新するよう修正しました。
パネルは設定対象の枠の確定済み配置と外見指定を表示し、編集中のカーソルや候補には追従しません。
編集中に差し替えを停止する動作は継続します。修正版はビルド確認済み、実機表示は未確認です。

## 動作

初期設定では OrnamentS の index=0（左外側）に実際に置かれているアイテムの
メッシュと材質を「まろやかなハチの巣ライト / 119074 / fld_cst_032_02」に置き換えます。
取得済みログでこの枠に置かれていた実アイテムは「ノーブルな調理セット / 119080」です。
実アイテムが別のものでも、対応構造であれば適用します。

配置ID・効果マスタ・所有数・ゲームのセーブデータを書き換えません。
元の GameObject・Transform を保持し、MeshFilter.sharedMesh と MeshRenderer.sharedMaterials のみ変更します。
表示用 Mesh / Material は複製し、無効化・対象変更・編集開始時に元へ戻して複製を破棄します。
表示用リソースは Permanent キャッシュで要求し、参照するテクスチャが存続するようにします。
ゲーム側でのキャッシュ破棄挙動は実機で検証が必要です。MODから共有キャッシュを解放しません。

## 導入と最初の検証

1. ゲーム終了中に `BazaarDecorTransmog/bin/Release/net6.0/BazaarDecorTransmog.dll` を
   ゲームの `BepInEx/plugins` に上書きコピーします。旧版と二重配置しないでください。
2. セーブをロードして自分のバザール店舗へ移動します。
3. 左外側の小オブジェがハチの巣ライトの見た目になるか確認します。
4. 左上の確認パネルで Actual / effects（実アイテム）と Visual target（外見指定）を確認します。
5. `Disable / restore` → `Enable transmog` で外見が戻る・再適用されるか確認します。
6. 通常の装飾編集を開きます。編集開始前に元の見た目へ戻し、編集モード中は差し替えを停止します。
7. キャンセルして閉じます。通常表示のモデルが戻った後に再適用されるか確認します。
8. エリア移動して戻り、表示が再適用されるか確認します。
9. ゲーム終了後に `BepInEx/LogOutput.log` を作業フォルダへコピーします。

ゲーム内セーブは最初の検証に不要です。実機の表示・IMGUIパネル・非同期読込・復帰は未検証です。
日本語表示名のフォントが欠ける場合も、IDとログで対応を確認できます。

## 設定

ゲーム起動で生成・追記される `BepInEx/config/com.icy.bazaardecortransmog.cfg`:

```ini
[Prototype]
Enabled = true
ShowPanel = true
SlotIndex = 0
VisualItemId = 119074
VisualModelName = fld_cst_032_02
```

設定ファイルの直接編集はゲーム終了中に行い、再起動して反映します。
パネルの切替は Enabled を更新し、BepInEx の通常設定保存に従って保存されます。
オフにすると次回も無効なので、検証を再開するときはパネルか設定からオンにします。
SlotIndex は0〜3の小オブジェ枠のみ。VisualItemId と VisualModelName はセットで指定します。
IDが別モデルを指していたら、カテゴリ＋モデル名の完全一致が一つだけある場合に現在のIDを解決します。
候補が不明・複数なら適用しません。表示名だけでの曖昧検索は行いません。

今回の保存は「1枠分の設定」です。名前付き複数プリセットや専用JSON形式は次段階です。
設定は全セーブ共通。セーブ別の紐付けはまだありません。

## 対応範囲

- 小オブジェのみ。元と外見先の両方が子を持たず、Transform / MeshFilter / MeshRenderer のみであることを実行時に確認。
- 棚、テント、大オブジェ、特殊オブジェ、アニメーション、Collider付き、DLC外見、空き枠は対象外。
- 所持済み外見だけに限定する判定は未実装。今回の既定外見は取得ログで設置されていたもの。
- 位置・角度・スケールは元のまま。異なるモデル間のサイズ・材質表現は実機で確認する。
- 閉店専用モデルの差し替えは未実装。観測できた通常の BazaarMyShop 内の1枠を対象とする。
- パネルはマウス操作の検証UI。ゲームパッド操作や本格的な外見選択UIは未実装。
- 読込が20秒で完了しなければ中断。パネルでOFF/ONすると再試行できる。

## 判定ログ

- `PrototypeReady`: 試作フックとコンポーネント登録が完了。
- `TransmogRequest`: 実アイテム、外見アイテム、枠、モデル名。
- `TransmogApplied`: `unchanged:true` が期待値。適用直前直後の観測値を before / after に記録。
- `TransmogRestored`: 元のメッシュ・材質へ戻した。
- `TransmogSkipped`: 未適用の理由。構造不一致・曖昧なID等。
- `DiagnosticError`: 診断／試作側の例外。表示の問題とあわせて確認する。

比較対象は全配置ID、パッシブ・シリーズ効果の有効マスタID、通常シリーズ×拡張分類ごとの
購入数・価格・ハッピーエナジー・鮮度・品質・ボーナスゲージ値、富豪・流行の値です。
来客嗜好辞書など全内部状態を網羅していないため、`unchanged` は比較対象がその瞬間に同一だったことを示します。
販売結果の完全な同一性や、非同期処理後の不変性まで証明するものではありません。
比較に失敗した場合は適用を中止し、書換え後に不一致が出た場合は外見を復元します。
