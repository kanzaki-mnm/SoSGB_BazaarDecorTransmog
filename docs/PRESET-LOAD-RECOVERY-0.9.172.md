# プリセット読込後のモデル更新失敗時の復元（0.9.172）

## レビュー指摘と対応

0.9.169で追加したプリセット読込後の即時Tickと着地演出は、共通の例外処理で包み、失敗時は姿勢だけを復元していた。Tickはrendererの表示状態も変更するため、その途中で例外が発生すると非表示状態や途中の復元情報を残す可能性があった。

この共通処理を、モデル更新と演出の2段階へ分離した。

- 即時Tickが例外を投げた場合: 通常の更新経路と同じslot.Restoreを使い、マスク、renderer、陳列台のmesh/material、外見clone、保留中コールバックを復元／無効化する。そのslotの演出要求は行わない。
- 即時Tickが正常に戻った場合: 着地を要求する。非同期モデル読込の完了を意味するフラグではない。未読込モデルの演出は既存の準備完了判定で待機する。
- 演出だけが失敗した場合: 姿勢を復元し、適用済みの外見を維持する。
- 復元自体が失敗して既存GuardがModを停止した場合: 後続slotの更新・演出を開始しない。

正常時の読込、ドスン、保存内容、連携APIは変更しない。Presetsプロジェクトは変更していない。

## 検証対象

通常のプリセット読込後に全配置の外見と着地が維持されること。モデル更新失敗時と演出失敗時の復元先はコード上で確認する。既存のID・保存・独立復元テストはUnityのrenderer例外注入を含まないため、実機での例外経路再現とは区別する。
