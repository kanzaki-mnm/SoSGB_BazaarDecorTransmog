# プリセットUI：調査と設計案

2026-09-20。v0.9.88を対象にした静的調査。ゲーム機能・DLLは変更していない。

## 目的と画面構成

transmog全11枠（テント1、棚3、小物4、大物3）を名前付きで保存・読み込みする。「プリセット」は機能名として使用可能。

みための変更 → ＋ → 保存／読み込み → スロット一覧 → 保存時のみ名前入力。
各階層のB/Escは一段戻る。ダイアログ表示中の入力が背後のみため編集に届かないようにする。

一覧は左に保存スロット名、右に選択スロットの11枠の内容を表示する案。カーソル移動は情報のプレビューだけとし、読み込み決定で初めて現在のみため一式を置換する。保存一覧の空き枠には「空きスロット」、読み込み一覧では空き枠を選択不可にする。

## 確認できたAPIと制約

調査元は `../decompile_Assembly-CSharp_dll/BokuMono/`。これらはIL2CPP相互運用ラッパーであり、メソッド内部のゲーム処理そのものではない。型・引数・フィールドの存在は確認済みだが、副作用・実際の表示・既定キーは未検証。

| 用途 | 候補 | 確認事項／未確認事項 |
| --- | --- | --- |
| ＋入力 | `ControllableUI.OnStart()`、`GamePadButton.Start`、`GuideKey.Start` | 入力経路が存在。実際の＋割り当てとMenuアクションへの変換は実機確認が必要 |
| キー対応 | `InputGamePadKeyBindConverter.ConvertButton`、`SerializableKeyboardKeyBindSet.GetKeyBind(InputAction)` | 現在のアクションセットから対応キーを調べる経路あり。Enter/Escと競合しないとはまだ断言できない |
| 保存／読み込みの2択 | `ChoicesData(List<uint>, Action<int>, ...)`、`UIDefaultDialogData`、`UIManager.OpenDialog(...)` | 既存の選択ダイアログを使う候補。独自文言は既存i18n＋限定したテキストID処理で供給する案 |
| 店舗一覧 | `UIBazaarMaxPriceCustomLogPage.bazaarCustomPartsIconList` | `List<UICustomPartsListItem>`を持つ。ページ全体には実効果・最高売上記録への依存もあるため、行部品の再利用を優先 |

| 入力制約 | `KeyboardMasterDataBase`、`KeyboardSteamMasterData` | 最小／最大文字数、キャンセル可否、確認文ID、入力文ID、禁止文字の設定あり |

名前入力の`KeyboardType`は主人公、牧場、動物、Nickname等の固定用途で、汎用Presetはない。既存用途をそのまま呼ぶと動物向け文言や文字数制限が残る可能性がある。プリセット入力中だけ独立したデータを返すか、入力ダイアログを直接構成できるかを次に検証する。共有マスタの恒久変更はしない。IME、ゲームパッドでの入力、キャンセル、空文字、確認画面も確認対象。

＋に対応するキーボードキーは現時点で未確定。Menu状態の実際の割り当てを取得し、Enter/Escや既存操作との競合を確認してから採用する。競合する場合は専用キーを提案する。フッター表示と実入力は同じ割り当てを使う。

## 既存保存処理を活かせる部分

`BazaarDecorTransmog/Presets.cs`に`VisualPreset`、`VisualSlot`、検証・JSON保存処理がある。保存先は`BepInEx/config/com.icy.bazaardecortransmog.presets.json`。一時ファイルとバックアップを使う既存保存処理を利用できる。

保存対象は各枠のReplacement／Actual／Hidden。Actualは現在の実効果アイテムIDに固定せず「実効果のみためを使う」という選択を保存する。未記載枠もActualとして表示・適用する。右側一覧ではActualを⟳＋説明、Hiddenを🚫＋「表示しない」で区別する。Actualの現在の実効果アイコンを添える場合、それは保存された固定アイテムではないことが分かる表示にする。

現在の`PrototypeController.Save()`は名前をキーに追加／上書きする。要求の「スロットを選んで保存・改名」とは異なるため、安定したスロットIDと表示名を分離する設計が必要。既存ファイルは順序を保って移行する案。名前変更で別スロットを上書きしないこと。

現在の`CyclePreset()`は未保存編集があると切替を拒否するため、そのままでは要求の読み込みに合わない。専用Load処理で保存済みデータをコピーし、現在の全枠を置換する。選択中のモデル・⟳アイコン・チェックマーク・説明欄も一緒に更新する。プレビュー一覧に触れただけで`LoadDraft()`を呼ばない。

保存はディスク保存成功後にメモリ内一覧を更新する。名前入力キャンセルや保存失敗で既存スロットを消さない。読み込み前に全データを検証し、解決できないアイテムがある場合の扱いを決めてから適用する。

## 未決事項と推奨案

- スロット数：固定数か、保存一覧末尾の「新規スロット」で追加する方式か。まず後者なら上限の恣意的な設定を避けられる。
- 名前の長さ：既存保存側は60文字以内だが、UI上の上限は別途決める。動物用の8文字をそのまま流用しない。
- 同名：スロットIDで識別すれば許容できるが、一覧の識別性を考えて方針を決める。
- 上書き・未保存編集の置換：確認を入れるか。操作回数との兼ね合いで決定する。
- 読み込み後の再起動時の扱い：現在は選択プリセット名をconfigに記録する。ID方式への移行で参照を更新する。

## 2026-09-21 実機検証追記

- ＋はゲームパッドのStart／キーボードのTabとして届く。2択の公式`UIDefaultDialogData`は、キャンセルをこのダイアログに限定して処理すればB/Escで閉じられる。閉じる際の`CloseDialog`の`isMaskLeave`は`false`にする。
- 名前入力は`KeyboardType.BuyPetAnimal`を利用できる。Steamの元データは`InputDialogId=101031`、`ConfirmDialogId=101045`、1～8文字。入力中に該当する公式文言IDの表示文字だけを差し替えれば日英の専用文言が出る。確認文の`{0}`は自動展開されないため、`KeyboardManager.inputedText`をこちらで埋め込む。キャンセル可否はこの入力要求のコールバックが一致する間だけ変更する。
- 独自の文言IDを`KeyboardSteamMasterData`のコピーに渡す方式では、名前入力画面が開かなかった。公式UIの事前検証かロード経路に依存すると見られるので、現時点では採用しない。名前の上限は公式の8文字のまま。
- `UICustomPartsListItem`は、起動後まだ「最高売上時の記録」内の店舗情報画面を開いていないと`Resources.FindObjectsOfTypeAll`で0件。開いた後は22件、`UIBazaarMaxPriceCustomLogPage`は2件となり、各行にはカテゴリ画像・オブジェ画像・名前欄がそろっていた。したがって、現在ロード済みの行だけに依存する実装は避ける。`UIPrefabsManager.Load(UILoadKey.UIBazaarMaxPriceCustomLogPage, callback)`でページのプレハブを表示せずにロードできるか、またはMod側で同じ構成の行を作るかを次に検証する。
- v0.9.100で上記のページロードを実機確認。未表示の状態では行0件・ページ0件だったが、`UIPrefabsManager.Load`の完了時にはキャッシュにページ1件と行11件が存在し、11行の各UI部品が取得できた。画面遷移やプリセットメニューの開閉にも変化なし。プリセット一覧ではこのロード済みプレハブをテンプレートとして利用できる見込み。実装時はロード完了前に一覧を表示せず、失敗時はプリセット一覧のみ開かない形にする。公式ページ自体の`ShowPage`や`GetUIPageData`は呼ばず、ゲーム本来の履歴・最高売上データに触れない。

## 2026-09-21 キャンセル可能なメニュー部品の再調査

前項の「2択の公式ダイアログはB/Escで閉じられる」は後の実機検証で否定された。現在の`UIDefaultDialogData` + `ChoicesData`方式では、B/Escが末尾の選択肢へ渡る場合がある。`ChoicesData`のコンストラクタにはキャンセル専用コールバックがなく、`CancelAction()`と`CancelAction(int)`がある。Mod側から公式`UIDialog.OnCancel`へ割り込む試案は取り下げた。

ポーズメニューの`UIPausePage`は`UIPage`を継承し、`UIGroupCommon group`、`GetUIPageData()`、`OnCancel(Phase)`、`CloseThisMenu(Action)`を持つ。選択行は`ChoiceData`、入力は`UIData`から返す`UIAction`を使う構成。`UIAction`には`onEast`（キャンセル側）と`onSouth`（決定側）の個別コールバックがある。これはB/Escを「最後の選択肢の決定」から分離できる有力な方式。ただし`UIPausePage`自体はセーブ・ロード・終了など専用処理を持つ画面であり、プリセットから直接開く候補にはしない。

次の試作候補は、既存の`UIGroupCommon`・`ChoiceData`・`UIData`・`UIAction`を利用し、Mod所有の選択画面に`onEast`で一段戻る処理、`onSouth`で選択決定処理を割り当てること。公式クラスのキャンセル動作は変更しない。IL2CPPラッパーから確認できたのは型・引数・フィールドまでなので、入力フォーカスと画面の開閉は小さな検証版で実機確認が必要。

ユーザー承認の代案として、v0.9.107では既存ダイアログの選択肢末尾に「閉じる」「戻る」を追加した。B/Escが末尾の選択肢を実行するゲーム標準の挙動を利用し、`ChoicesData.CancelAction`へのHarmonyパッチを削除した。2択メニューのB/Escはみため編集へ、スロット一覧のB/Escはプリセットメニューへ戻す。これはコード上の接続であり、実際の操作とマスク・プレビュー除去は実機確認が必要。

## 2026-09-21 v0.9.108 保存接続

v0.9.107でB/Escによる「閉じる」「戻る」と日英表示を実機確認済み。v0.9.108では名前入力の成功コールバックを実際のJSON保存につないだ。既存の`Default`などのプリセットはそのまま保持し、UIの3枠には1～3の`UiSlotIndex`を付けたプリセットだけを対応させる。スキーマは6へ上げ、旧ファイルは読み込み時にメモリ上で移行し、最初の保存時に書き戻す。名前入力キャンセル・重複名・保存失敗時には既存ファイルやUI枠を変更しない。保存後は対象枠に名前を表示する。実機での名前確定、一覧再表示、再起動後の復元は未確認。読み込み側はまだ旧試作のまま。
