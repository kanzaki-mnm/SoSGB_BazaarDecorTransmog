# ホバー処理の確認とプリセット読込時の着地（0.9.169）

## レビュー結果

現状は、単一の状態機械として完結した構造ではない。SlotAppearanceがモデル差替えに加えてホバー・着地を担当し、AppearanceEditorUiが終了確認前の姿勢と公式UI復元を担当している。複数のフラグを持つため、状態の組合せを追う負担は残る。ただし、終了確認の選択肢ごとに異なる着地処理を継ぎ足す構造にはなっていない。終了確認前の姿勢を記録し、共通の復元経路へ渡している。

残す理由がある補正:

- モデル読込後のホバー開始: 非同期差替え中に旧モデルを先に浮かせないため。
- native rootの絶対高さ補正: 外見モデルは公式モデルの子なので、親の浮遊と独自浮遊を二重加算しないため。
- 終了確認前の姿勢保持: 保存・破棄・やめる・変更なしで戻る際に、公式の再フォーカスが姿勢を変えないため。
- 着地後の高さ維持と短時間の公式遷移補正: 公式アニメーション／親Transformの更新順による浮き直りを抑えるため。

固定の地面高さ0、浮遊量0.5、遷移補正時間0.6秒への依存は残っている。Unityオブジェクトの破棄を許容する復元時のcatchも残す。これらを削除できると断定する材料はない。純粋な姿勢制御を別クラスに分離する余地はあるが、今回の機能追加と同時の全面改修は避けた。

## 動作仕様

- プリセット読込成功時、表示対象の全slotを着地させる。同じプリセットの再読込でも演出する。
- 固定外見は対象モデルの適用完了後に演出を始める。読み込み時間によってslotごとの開始時刻は異なる。
- Actualは現在の公式モデルのrootを動かす。非表示設定と実配置が空のslotは演出しない。
- 非表示が許可されないカテゴリのHiddenは、従来のActualフォールバックと同じ扱い。
- 通常の単体Actual／Hidden決定に新たな着地は追加しない。
- プリセット保存・削除・読込失敗・終了確認の破棄には、新たな一括着地を追加しない。
- 保存形式、実配置・実効果・バニラのセーブへの書込処理は変更しない。

## 検証

Releaseビルド成功（警告0・エラー0）。既存のID・保存・復元テスト97項目成功。これらはUnityのアニメーションを検証していない。

実機確認待ち:

1. 固定外見・Actual・非表示を混在させたプリセット読込。テント／陳列台3台／小物全配置が着地し、非表示は出現しないこと。
2. 同じプリセットの再読込と、モデルが初めて読み込まれるプリセット。差替え後のモデルに演出が付くこと。
3. 同時演出の音量・エフェクト密度が自然か。公式API内部の音の合成はinteropの宣言だけでは判断できない。
4. 完了通知を閉じて方向入力・タブ変更・再読込。遅れて別のオブジェが落下しないこと。
5. 通常の単体決定と、その後の保存／破棄／やめる／変更なし退出で、浮遊・着地の姿勢保持が変わらないこと。
