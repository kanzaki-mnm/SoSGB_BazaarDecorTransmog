# Bazaar Decor Transmog — 旧README・試作履歴

以下は旧バージョンの資料です。導入・操作・保存先は現在の [README](../README.md) を参照してください。

## 保存できない場合（0.9.166）

「反映してもどる」やプリセット保存が失敗した場合は、通知を閉じると編集画面へ戻ります。
詳細はゲームフォルダ内の `BepInEx/LogOutput.log` を確認してください。
破損して復旧できないデータや、現在のModが対応していない新しい保存形式は上書きしません。

初期状態へ戻したい場合はゲームを終了し、`BepInEx/config/BazaarDecorTransmog.cfg` と
`BazaarDecorTransmog.cfg.bak`（存在する場合）を両方とも別フォルダへ退避してから再起動してください。
現在のみためと保存プリセットは初期化されます。バニラのセーブデータを操作する必要はありません。
新しいModで保存されたデータの場合は、初期化の前に対応するModバージョンへ戻すことを検討してください。
権限不足やディスク容量不足などが原因の場合は、その問題も解消する必要があります。

以下は各試作段階の履歴です。

変更画面を開いた直後は実配置・実効果を編集し、フッターの「みためを変更」から外見編集へ入ります。
戻る操作ではTransmogをOFFにせず、実効果編集へ戻ります。詳細は [MODE-0.9.md](MODE-0.9.md) を参照してください。

## 導入

1. ゲームを終了する。
2. `BazaarDecorTransmog/bin/Release/net6.0/BazaarDecorTransmog.dll` をゲームの `BepInEx/plugins` にコピーする。コピーするのはこの DLL だけ。
3. ゲームを起動してセーブをロードする。

ビルドはゲームフォルダに自動コピーしません。同名プラグインの複数配置は避けてください。

## 最初に採取する操作

1. バザールの自分の店に移動する。
2. 装飾の編集画面を開く。
3. 同カテゴリのオブジェを数種類選択してプレビューする。可能なら小・大・特殊それぞれを確認する。
4. 一度キャンセルして編集画面を閉じる。
5. もう一度開き、オブジェ1個を通常操作で変更・確定する。
6. 別エリアへ移動し、バザールに戻る。
7. ゲームを終了し、`BepInEx/LogOutput.log` をこの作業フォルダにコピーする（例: `logs/first-run.log`）。次の起動で上書きされる前に確保する。

この操作による通常の配置変更はゲーム側で行われます。ゲーム内セーブの実行は最初の調査では必須ではありません。
閉店時・開店時やセーブ再読込は、最初のログを確認した後に不足分を追加採取すれば十分です。
操作順と「どのオブジェを変更したか」を短くメモすると照合しやすくなります。

## ログの確認

`BDT ` に続く JSON がこの MOD のログです。連番 `seq` で順序を追えます。

| kind | 内容 |
|---|---|
| `Session` | MOD・ゲーム・Unity のバージョンと言語 |
| `PatchReady` / `Ready` | 各パッチの登録結果。0.1.1 は `installed:6, expected:6` が想定 |
| `CatalogPending` | マスタ未準備。次の対象イベントで再試行 |
| `CatalogBegin` / `Part` / `CatalogEnd` | 全パーツの ID・カテゴリ・モデル名・表示名・効果参照・DLC ID。成功時は起動ごとに1回 |
| `DuplicateCategoryModel` | 同カテゴリ・モデル名が複数IDで使われている |
| `DuplicateDisplayName` | 同じ表示名が複数IDで使われている |
| `ManagerEvent` / `Layout` | 操作直後の現在配置・編集中配置。非同期処理の完了を意味しない |
| `ModelRequest` | 通常モデルの読込要求。アイテムID・カテゴリ・設置位置 |
| `ResourceRequest` | モデル名によるリソース読込要求。隣接するログと同一要求とは限らない |
| `ClosedModelRequest` | 閉店時のパーツ読込要求。カテゴリ・設置位置 |
| `Prefab` | 初期化に渡されたモデルの階層とコンポーネント名。同カテゴリ・同名は1回、最大160ノード・深さ12 |
| `ShopSnapshot` / `LiveModel` | カーソル移動・編集モード終了時に生成済みモデルを観測。階層は `Prefab` の `source:live-instance` として出力 |

`BDT DiagnosticError` は診断側の例外です。同じ処理のエラーは原則1回だけ出します。
`Ready` が出ても全フックがゲーム内で呼ばれた保証はないので、ログ全体を確認します。
表示名は `CustomPartsMasterData.Id` と `ItemMaster` の同じIDを照合しています。
`itemMasterMatchedById:false` や `name:null` は欠落をそのまま記録し、推測で別の名前を付けません。
マスタ一覧は所持・アンロック済みアイテムの一覧ではありません。
Prefab の階層ログは通常側の初期化入口と生成済みモデルが対象です。閉店側は今回、要求経路まで記録します。

## 停止・削除

ゲーム終了後に DLL を取り除くと停止します。または生成された
`BepInEx/config/com.icy.bazaardecortransmog.cfg` の `[Diagnostics] Enabled` を `false` にして再起動します。

## ビルド

```powershell
dotnet build .\BazaarDecorTransmog\BazaarDecorTransmog.csproj -c Release
```

ゲーム配置先が違う場合は `-p:GameDir="ゲームの絶対パス"` を指定します。
既存ゲームの `BepInEx/core` と `BepInEx/interop` を参照し、依存 DLL は成果物へコピーしません。

## 調査後の判断

- ID・モデル名・カテゴリの照合による保存方式が可能か。
- カテゴリ＋モデル名が一意か。重複時は補助情報が必要か。
- 通常表示、編集プレビュー、キャンセル、確定、閉店時でどの読込経路が使われるか。
- オブジェ Prefab に描画以外のコンポーネントが含まれるか。

静的調査の根拠は `RESEARCH.md` を参照。
