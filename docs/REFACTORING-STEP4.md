プレビューはpartialによるファイル分割とする。画面の終了callbackと位置復元を別々の寿命に変更せず、従来の所有関係・実行順を維持するため。
削除表示になる旧ファイルは上記の新ファイルへ移動・分割したもの。変更前の実装は基準コミットから参照・復元できる。

## 維持した境界と後続対象

- 保存データの型名・プロパティ・schema 9・読込/復旧/保存アルゴリズムは維持。保存層とAppearanceSessionは移動・改名以外の差分がないことを確認した。
- Mod GUID、Harmony ID、Patchの登録対象と順序、IL2CPP登録コンポーネント名PrototypeDriverを維持。Driverはファイルのみ分離する。
- Update / LateUpdate、0.5秒周期、120フレームの待機上限、閉じるcallbackと座標復元順は維持する。
- バニラのセーブ・実効果データ・共有マスタ・共有prefabへの書き込みは追加しない。
- ClosedTentProbe / ClosedShelfProbeは登録済みPatchでもあるため、今回は呼出し先の改名のみ。閉店モデル固有の寿命は統合しない。
- UIManagerの全体キャッシュ、通知instanceの特定方法、例外時の一括無効化、将来schemaの扱いは変更していない。これらの寿命・異常系を伴う変更は次段階で扱う。
- RuntimeIndexの手計算と公式一覧のフォールバック順序は維持。未知構造の扱いを今回の軽量化に混ぜない。

## 実機確認後の追加修正: マップ入場時の中央陳列台

第4段階の実機確認で、他マップから戻ったとき中央陳列台だけ実効果側のモデルが一瞬見えるとの報告。他の操作は正常とのこと。
上記の責務整理とは区別して、表示タイミングの不具合を修正した。

- 原因候補: 閉店用中央陳列台は別インスタンスで、従来のClosedShelfProbeは0.5秒周期で読み込みを開始し、完了まで実モデルを描画していた。この経路は第4段階より前から存在する。
- 置換: 既存のPartsObject読込完了Postfixから陳列台にも通知し、この時だけ周期待ちを飛ばす。新しいPatch対象は追加しない。
- 読み込み中: 検証済みの棚本体MeshRendererだけを一時非表示にし、成功時に外見を差し替えて元のenabled状態へ戻す。商品、アイコン、当たり判定、実配置ID、保存データは変更しない。
- 復元: 読み込み失敗、不一致、例外、タイムアウト、元モデル変更、通常のRestoreで一時非表示を解除する。世代の古いcallbackは新しい要求に触れない。
- 再試行: 同じモデルインスタンスを隠すのは最初の一回だけ。失敗後の定期再試行ではバニラ表示を保ち、繰り返し非表示にしない。タイムアウトのチェック間隔と20秒の上限は維持する。

追加修正の検証: Releaseビルド警告0・エラー0。復元分岐と世代チェックをコード上で確認。Unity実機での瞬間表示と失敗時描画は未確認。
実機では他マップとの往復（初回・繰り返し）、閉店/開店、編集終了後、実配置追従を選んだ棚の表示を確認する。
外見データの読み込みが遅い場合、待機中に棚本体が短時間見えない可能性はある。

## 最終確認

ユーザーの実機確認で、責務整理・軽量化後の操作と、中央陳列台がtransmogモデルのみ表示されることを確認済み。この段階は対応完了。
追加修正を含めたセルフレビューで修正必須の明確な不具合は見つからず、Releaseビルドは警告0・エラー0、IdentityChecksは76項目成功。
読込失敗・タイムアウトの表示復元はコード確認までで、実機での故障再現は後続の異常系検証対象とする。
上記の「未確認」「commit・pushは行っていない」は各実装完了時点の記録。
