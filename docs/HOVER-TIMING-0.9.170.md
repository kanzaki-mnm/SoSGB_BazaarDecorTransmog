# 初回タブ切替のホバー補間（0.9.170）

0.9.169のホバー・プリセット着地はユーザー実機確認で良好。ただし編集画面に入って初めて訪れるタブだけ、ホバーが瞬間移動に見えるとの報告。

## 原因候補と変更

従来は開始時のTime.unscaledTimeとの差を0.14秒のホバー時間で割っていた。開始後、最初の描画までのモデル生成・UI初期化等で時間がかかると、次の更新で進捗が1に達する。初回だけ起きる観測と整合するが、実機のフレーム時間計測で原因を確定したものではない。

開始時刻の保存を、更新ごとの経過時間加算へ置換する。開始フレームおよび同一フレーム内の重複更新では進めず、以降はunscaledDeltaTimeを最大1/30秒に制限して加算する。通常30fps以上では従来の速度を維持し、長い停止による中間姿勢の飛ばしを抑える。戻りのホバー補間も同じ扱い。

変更の影響はホバーの時間進行のみ。30fps未満では実時間での補間が少し長くなる。補間開始の最初の書込は次フレームになる。読み込みそのものの停止時間を短縮する変更ではない。

ドスン、終了確認前の姿勢保持、モデル読込順序、Harmony対象、データ保存は変更しない。0.9.169の未コミット変更を保持。

## 検証

実機確認対象: 編集画面へ新規入場後、各カテゴリ内の各タブへの初回移動と2回目以降の移動、Actual/固定外見、素早い往復移動、通常決定とプリセット読込のドスン、終了確認後の姿勢保持。

Unityでの再現確認は未実施。初回だけの瞬間移動が残る場合は、公式側のTransform上書きや開始前の姿勢について追加調査する。
