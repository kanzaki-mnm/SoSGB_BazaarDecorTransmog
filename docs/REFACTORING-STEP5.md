# 第5段階: 異常系の安全性

2026-09-22。基準は `refactor/cleanup` / `17563b0`。確認用DLLは **0.9.157**。

通常時のUI、保存形状（schema 9）、6スロット、同名保存、CurrentAppearance、ホバー・着地の仕様は維持する。
以下は設計書第7・8節に沿って、異常時の扱いを厳密化した変更。正常動作の実機確認はこの版では未完了。

## 保存の障害境界

- schema 1〜9と未知のJSONプロパティは従来どおり扱う。
- 将来schemaを本文の型へのデシリアライズ前に判定する。将来schemaの本体から古いsnapshot/bakへ戻らず、読み書きを拒否する。上書き対象になるbakが将来schemaの場合も保持する。
- 主ファイル不在でもbakがあれば復旧を試す。起動時の復旧不能時は元ファイルを保持し、空の外見へフォールバック、保存をブロックする。
- Saveは入力のコピーを検証する。schemaとPreviousValidStateを呼出し側へ戻すのはディスク置換成功後だけ。
- 一時ファイルを書いて再読込検証し、正常な主ファイルは `File.Replace` でbak生成と置換を行う。初回作成は上書きしない `File.Move`。失敗時に従来のCopy→Moveへフォールバックしない。
- snapshot/bakから復旧した主ファイルの破損バイトをbakへコピーしない。既存bakを維持し、復旧した正常状態を新しい本体のPreviousValidStateへ保存する。外部bakがない場合も正常snapshotは本体に保持される。次回の正常保存で通常のbakを生成する。
- 本体もbakも復旧できなければSaveでも上書き拒否。失敗した一時ファイルは可能な範囲で除去する。
- 運用ログの出力失敗をデータ破損と取り違えない。

対象はMod専用ファイルだけ。バニラのセーブデータ、実配置ID、効果データへの書き込みは追加していない。
原子的置換はWindowsのファイルシステムAPIを使用する。電源断・ストレージ故障・別プロセスとの同時編集まで完全保証するものではない。

## 表示・起動・UIの障害境界

- 起動時の翻訳/設定読込からPatch登録までを例外境界に含める。起動失敗は新規操作を止め、表示復元を試し、**自分のHarmony IDだけ**をUnpatchSelfする。
- `Recovery.Run` は各復元を独立して試し、全処理後に失敗をまとめて通知する。失敗を握りつぶして次の外見適用に進まない。
- 各モデルのrenderer、mesh、material、cloneの復元を分離。成功した復元記録だけを捨て、失敗分は再試行できるよう保持する。clone非表示に失敗しても破棄は別途試す。
- モデル更新/読込callbackの例外では該当スロットの復元を試す。世代番号はUnityアクセスより先に更新し、古いcallbackを失効させる。復元まで失敗した場合はModを停止し、他スロットの復元も試す。
- 稼働中は一括Unpatchしない。すでに開いたModダイアログの閉じる経路を保持する。
- プリセットUIのcallbackは表示セッションの世代を捕捉する。正常終了・異常中断で古い保存/削除/再表示callbackを失効させ、選択中スロット、名前入力、継続callback、位置・プレビューを後始末する。
- プリセットUI異常時は再起動まで新規プリセットUIを停止する。公式UIの現在キーとMod専用IDを照合できる自分のダイアログだけ、公式CloseDialogで閉じる。名前入力の取消も自分のcallbackが所有している要求だけに行う。非同期で遅れて現れた自分のダイアログも監視対象とする。
- 外見UI全体の例外やプリセット読込のロールバック失敗では、Mod停止・プリセット中断・タイトル/フッター/選択肢/モデル復元を試す。外見用選択肢の除去または異常時のリスト再構築に失敗した場合は、実配置書込を抑止するActive状態を保持する。完全な復元ができない場合は再起動が必要となる。
- 完了通知はinfoId、スロット一覧はMod専用の選択肢IDで対象を識別する。本文差し替えとB/Esc許可を、無関係な公式/他Modダイアログへ適用しない。

## 削除・置換とリスク

| 置換した処理 | 不要/危険と判断した理由 | 置換先 | 壊れる可能性がある箇所 |
| --- | --- | --- | --- |
| 将来schemaをClamp/9代入して復旧 | 新しい保存内容を失う | バージョン先行判定・拒否 | 未来版データでは保存不可になる |
| 主ファイルをCopyしてからMove | 本体置換失敗前にbakが変わる、破損本体をbakへ移す | 検証後のFile.Replaceと復旧元別のbak扱い | ファイルロック、アクセス権、非対応ファイルシステムでは保存拒否 |
| 復元の直列実行・記録の一括破棄 | 1件の例外で他の復元が未実行 | 独立実行・失敗記録保持 | ホバー、閉店モデル、棚の商品を含む表示経路 |
| Patch途中失敗をログだけで終了 | 部分的なPatchが残る | 新規停止・自己IDの解除 | 起動失敗時のバニラ復帰（実機未確認） |
| 複数回使い回す生のUI callback | 中断後に古い遷移や保存を実行できる | 世代を捕捉したcallbackと終了時の破棄 | 保存→命名、削除→通知→一覧、キャンセル→再表示 |
| 最後のアクティブ通知/同じ行数の一覧を探索 | 他のダイアログを誤認し得る | Mod専用IDで限定 | 小型通知の本文・B/Esc、一覧プレビューの取得 |

Harmony Patch対象は増やしていない。共有prefab/マスタを編集する処理は追加していない。

## 0.9.159 の例外対応（0.9.160）

0.9.159ですでに停止したセッションは、ゲームを終了してDLLを交換し、再起動して確認する。
