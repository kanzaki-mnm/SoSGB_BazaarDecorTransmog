## 導入

ゲーム終了中に `BazaarDecorTransmog/bin/Release/net6.0/BazaarDecorTransmog.dll` を
ゲームの `BepInEx/plugins` に上書きします。起動後、旧configの Enabled がOFFならパネルでONにします。

## 最初の確認（開店する必要なし）

1. 装飾編集を開き、ゲーム側では設置中の小オブジェを選択した状態にします。
2. 左下のMODパネルで `Transmog: ON`、`Editor preview: ON` にします。
3. 4つの枠タブから変更したい枠を選びます。タブは設定対象を選ぶだけで、バニラ側のカーソルは動かしません。
4. Searchに名前の一部またはIDを入力し、`<` / `>` で表示候補を切り替えます。
5. Actual / effects（通常時）またはEdited placement（編集中）と、Visual targetが別々に表示されることを確認します。
6. 対応している枠の外見が変わるか確認します。パネル右上の `-` / `+` で折り畳めます。
7. 別の枠にも外見を指定し、両方が表示されるか確認します。`Use vanilla` は選択枠だけの指定解除です。
8. Save nameに `Test` 等を入力し、`Save preset` を押します。
9. 外見指定をもう一度変えて `Revert draft` を押すと、最後に読み込んだ保存済みプリセットへ戻ります。
10. ゲームを再起動し、保存したTestが選ばれ、外見指定が残っているか確認します。
11. 編集画面を開き直した場合、Editor previewは再度ONにします。開店中は通常通り自動適用する設計です。

ゲーム内セーブはプリセット保存に不要です。検証後はLogOutput.logを確保してください。
画面内で表示が変わらない場合は、その枠のStatusとTransmogSkippedを確認します。

## 編集画面での扱い

- 編集に入るたびプレビューOFFから開始します。明示的にONにした場合だけ外見を表示します。
- ONは設定した全4枠に作用します。タブはそのうち1枠の情報と外見指定を編集するものです。
- ゲーム側で別アイテムにカーソルを当てている間、その枠のバニラ候補プレビューを優先します。
  現在の編集中配置データと生成モデル名が一致した枠だけ差し替えます。
- バニラで配置確定すると、実配置・効果はゲームの通常処理で変わります。
  外見プリセットは独立しているため、バニラの編集キャンセルでMODの外見指定は元に戻りません。
  MOD側の変更を戻すにはRevert draftを使います。
- バニラ編集の開始・終了時には外見複製を解除して再評価します。
- 非同期読込は各枠に世代番号を持ち、候補切替や解除後に古いロード結果を適用しません。

## プリセット操作

- `<` / `>` やUse vanillaの変更はまずメモリ上のdraftにだけ反映します。
- Save presetで名前を指定して保存。同名ならその名前のプリセットを更新、新しい名前なら追加します。
- Previous / Next presetで保存済みプリセットを切替。未保存の外見変更がある間は切替を止め、Save / Revertを案内します。
- Revert draftは4枠とも現在の保存済み内容へ戻します。
- 名前付きプリセットの削除・ゲームパッド操作・セーブ別設定は今回未実装です。

## 保存先

ゲームの `BepInEx/config/com.icy.bazaardecortransmog.presets.json` に保存します。

```json
{
  "SchemaVersion": 1,
  "Presets": [
    {
      "Name": "Default",
      "Slots": [
        { "Index": 0, "ItemId": 119074, "Category": "OrnamentS", "ModelName": "fld_cst_032_02" }
      ]
    }
  ]
}
```

指定がない枠はバニラ表示です。枠0〜3は左外側・左内側・右外側・右内側です。
スロットのアイテムIDは実配置ではなく外見指定を表します。
選択中のプリセット名は従来のcfgの `[Presets] ActivePreset`、ON/OFFは `[Prototype] Enabled` に保存します。
全セーブで共通です。cfgの旧1枠設定を変更しても、JSON作成後の外見は変わりません。

保存は一時ファイルへ書き込み後に置き換え、以前のJSONを `.bak` に残します。
既存JSONが壊れている、未対応schema、重複名・枠・不正なカテゴリ等がある場合は上書きせず、
Recovery（バニラ表示）のdraftを使用してSaveを無効化します。ゲーム終了後に元JSONを修正するか、
バックアップを戻して再起動してください。JSONを直接編集する場合もゲーム終了中に行います。

## 今回の制限

- 対象は小オブジェ4枠のみ。対応している単純構造という制限は維持しています。
- 元と外見先が、子オブジェクトなし・Transform / MeshFilter / MeshRendererのみの場合に適用します。
- 候補一覧は非DLCの小オブジェマスタから作ります。所持判定・全候補の構造検査は事前には行わず、
  適用時に未対応なら元の表示を残してStatusに理由を表示します。
- 棚・テント・大／特殊オブジェ・アニメーション・Collider付き・DLC外見は引き続き対象外です。
- 閉店用モデルへの対応はまだありません。
- 効果比較は既存のサンプリング比較に加えて、編集中配置のIDも比較します。
  編集プレビュー時の効果値はその時点のバフ値であり、編集中の全効果を新たに算出する機能ではありません。
- 通常ON/OFF、再起動後の外見再適用、編集候補の変更・キャンセルの実機検証が必要です。
