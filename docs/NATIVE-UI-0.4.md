# 公式一覧を利用する外見編集実験 0.4.1

0.4.1: Appearance mode終了時にEditor previewもOFFにするよう修正しました。
0.4.0では一時モデルを解除した後もプレビューが有効で、次の更新で再生成されていました。
終了時は全枠のモデルを復元し、読込待ちを無効化します。決定済み外見ドラフトとプリセットは保持します。
開店中の通常Transmogは従来通り有効です。ビルド成功（警告0・エラー0）、実機での復元は確認待ちです。

## 検証手順

1. ゲーム終了中にDLLを上書きし、装飾編集画面を開く。
2. 小オブジェの変更したい設置枠を公式側のカテゴリタブで選ぶ。
3. MODパネル上部に追加された `Appearance mode: OFF` を押してONにする。
4. 公式一覧の候補を一度別のものへ動かす。フォーカス移動が外見プレビューへ渡されるか確認する。
5. 公式の決定操作を行う。実配置ではなく外見ドラフトに選択が残るか確認する。
6. 別候補へ移動し、公式の「戻る」を押す。この実験では外見モードを終了し、未確定のホバー候補だけ取り消す。
7. MODパネルのActual/Edited placementとVisual targetを見比べる。確定した外見を保持する場合はSave presetを押す。
8. 外見モードOFFで元の詳細欄が戻り、通常の装飾編集ができるか確認する。
9. LogOutput.logを確保する。最初の試験ではゲーム内セーブは不要。

旧版プリセットをそのまま読み込む。外見モードをONにするとTransmogとEditor previewを有効にする。
Editor previewは従来通り編集開始・終了時に解除される。モードのキャンセルは、決定済みの外見ドラフトまで
取り消す操作ではない。決定済み変更を戻す場合はRevert draftを使う。

## 再利用と切替

- `UIBazaarCustomPage.ShowPage`: 表示中ページを取得。
- `OnFocusIn`: モード中は元メソッドを呼ばず、外見プレビューへ渡す。
- `OnDeside`: 元メソッドを呼ばず、外見ドラフトを更新する。
- `OnCanacel`: 外見モードから通常編集へ戻す。
- `OnClose`: 残っているモード状態と一時プレビューを解除。
- `BazaarManager.SetCustomParts`: 外見モード中は呼出しを遮断する追加ガード。
- `OnShowDetail`: 外見モード中は通常の効果詳細を開かない。

候補・入力・タブの基礎は公式画面のまま。表示対象は元の所持品一覧や元の選択制約に従うため、
IMGUI検索側と候補範囲・選択可否が異なる場合がある。元の「設置中」マークや個数は実アイテム側の表示であり、
外見装備の印ではない。今回それらの表示は変更していない。

## 対象と制限

- 小オブジェ4枠のみ。カテゴリとスロットの対応はゲームの `ToPartsCategoryIndex` を呼び、ログに残す。
- テント・棚・大オブジェ・取り外し候補は外見モードでは決定しない。解除はMODパネルのUse vanillaを使う。
- DLC外見・動作スクリプト等を含むモデルの制限は従来通り。
- 外見モード中は公式の詳細・効果パネルを隠し、MODパネルに実配置と表示候補を分けて表示する。
- 本格的な公式風の専用詳細パネル、タイトル変更、外見用の装備マークは未実装。
- 公式メニュー側の全コールバックはラッパーだけでは把握できないため、実機で呼出し順とゲームパッド操作を検証する。

## ログと確認済み範囲

`NativeUiChoice` がフォーカス・決定と選択カテゴリ/スロット/IDを記録。
`NativePlacementBlocked` は通常配置変更ガードが止めた呼出し。
`ManagerEvent` の `native-ui:enter/exit/before-choice/after-choice` と続く `Layout` で
現在・編集中配置が変わらないことを照合する。外見適用自体は既存の `TransmogApplied` 比較も継続する。

ビルドは警告0・エラー0。インストール済みInteropのメタデータで、対象ページメソッド6個が
一意のシグネチャを持つことを確認した。Harmony適用、決定・キャンセル・プレビューの実動作は未確認。
