## 今回の変更

- 保存処理の `Plugin.Emit` 直接参照を、ホストが渡す `PresetStorage.Report` に置換。Unity/BepInExなしで製品の保存処理を検証するためです。Plugin起動時に従来のEmitを設定し、イベント名と内容を維持しています。
- schema 5、同名禁止、正常bakがある場合も破損主ファイルを拒否する古い期待値を、現行schema 9・同名許可・bak復旧へ修正。
- 失敗保存の入力を、既に有効になっていたschema 6から実際に不正な名前へ変更し、例外が出たことも検証。
- 6スロット、CurrentAppearance、埋め込み前回状態、外部bak、両方破損、旧schema 1〜9、未知プロパティ、検証失敗と一時ファイル作成失敗時の主ファイル/bak保持を追加。

製品側の変更リスクはロガー設定忘れによる診断欠落です。起動時設定とテストで通知経路を確認しています。保存・復旧・照合アルゴリズムやJSON形式は変更していません。

## 検証の境界

- schema 1〜9のループは最小データの受け入れ確認です。カテゴリ導入境界は既存テストで別途検証します。全旧バージョン実ファイルの網羅ではありません。
- 未来schemaのテストは「復旧データがない場合のLoad」とValidateの拒否のみ。未来schemaと埋め込み状態/bakの併存、Saveによるschema変更は既知の課題として残しています。
- 一時ファイル作成失敗は `.tmp` と同名のディレクトリで再現。主ファイル置換中の失敗・電源断・復旧後の再保存で正常bakを維持する検証は、後続の安全性改善で追加します。
- Unity/IL2CPPのダイアログ、ホバー、モデル再適用、実際のUIからの保存/読み込み/削除、ゲーム再起動は対象外です。実機確認は別途必要です。

詳細な後続方針は [リファクタリング設計案](../../docs/REFACTORING-PLAN.md) を参照してください。
